# SECURITY SPECIFICATION - CustomerPro Firestore Security

This document outlines the security architecture, invariants, and threat analysis for the CustomerPro Firestore database.

## 1. Data Invariants

1. **Customers (`/customers/{id}`)**:
   - Must contain unique `id` matching document path key.
   - NIK must be restricted / safe.
   - Field `price` cannot be altered by Sales Representative arbitrarily.
   - Status transitions can only be made by `Super Admin` or `Admin`.
   - `createdAt` is immutable.

2. **Invoices (`/invoices/{id}`)**:
   - `amount` must match the corresponding customer's package price.
   - Status changes (e.g. marking "Lunas") must restrict who can change them.
   - `createdAt` is immutable.

3. **Service Packages (`/servicePackages/{id}`)**:
   - Prices and configurations can ONLY be written by `Super Admin` or `Admin`.
   - Sales has strictly read-only access.

4. **Sales Representatives (`/salesRepresentatives/{id}`)**:
   - Sales users can access metrics, commissions and personal details but cannot change their own commission rate or target metrics. Only Admin can edit permissions.

5. **Commission Receipts (`/commissionReceipts/{id}`)**:
   - Highly secure commission records. Can only be generated by the system (Admin approval / state change) and are immutable once paid ("Dibayarkan").

6. **Notifications (`/notifications/{id}`)**:
   - Standard notification feeds, allowed to be updated (read/unread) by authenticated employees.

## 2. The "Dirty Dozen" Malicious Payloads

The following payloads attempt to break security parameters and must return `PERMISSION_DENIED`:

### Payload 1: Sales trying to upgrade their own commission rate
- **Target**: `/salesRepresentatives/sales-1`
- **Action**: Update `commissionRate` from `10` to `90`
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 2: Self-Allocating Custom Pricing to Customer
- **Target**: `/customers/cust-under-table`
- **Action**: Create customer with normal package but price set to `0` or `1`
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 3: Changing customer package status bypassing Admin limits
- **Target**: `/customers/cust-1`
- **Action**: Change customer `status` from `Nonaktif` to `Aktif` without Admin credentials
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 4: Arbitrary Invoice Forgiveness
- **Target**: `/invoices/inv-unreleased`
- **Action**: Transition `status` from `Belum Bayar` to `Lunas` without registering paymentMethod or matching pricing
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 5: Spoofing system-generated details on Invoice
- **Target**: `/invoices/inv-1234`
- **Action**: Creating a mock invoice for custom software with a high value.
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 6: Modifying immutable `createdAt` timestamps
- **Target**: `/customers/cust-1`
- **Action**: Changing `createdAt` to retrospective dates to manipulate metrics or history
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 7: Deleting crucial billing Invoice
- **Target**: `/invoices/inv-1`
- **Action**: Direct `DELETE` operation by unauthorized Sales Rep
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 8: Creating or editing Service Packages with arbitrary pricing
- **Target**: `/servicePackages/pkg-lite`
- **Action**: Sales writing discount entries directly to collections
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 9: Self-Assigned Commissions
- **Target**: `/commissionReceipts/comm-robbery`
- **Action**: Create commission receipt manually with inflated rate or arbitrary amount
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 10: Injecting 2MB payload or Poison ID as document ID
- **Target**: `/customers/CUST_VERY_LONG_ID_OR_MALICIOUS_CHARACTER_$$$_%#`
- **Action**: Attempt create with invalid identifier path string.
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 11: Modifying someone else's notification read status
- **Target**: `/notifications/notif-admin`
- **Action**: Update notification fields from unauthorized client account.
- **Expected Outcome**: `PERMISSION_DENIED`

### Payload 12: Changing customer GPS locations without authentication
- **Target**: `/customers/cust-2`
- **Action**: Non-authenticated write modifying location details.
- **Expected Outcome**: `PERMISSION_DENIED`

## 3. The Test Runner Spec

We enforce block-level rule assertions in `firestore.rules` and verify them.
All security conditions are implemented sequentially:
- First, standard static type checking.
- Then, role constraints (Super Admin / Admin vs Sales / Public).
- Secure fields with immutability guarantees.
